# Публичные бенчмарки клиентских интентов (экспериментальная ветка)

## Зачем

Этот эксперимент проверяет AMORPH AutoTrainer на двух внешних наборах с готовыми метками интентов. Это проверка кода и протокола, а не замена реальных обращений клиентов ТМК Юг.

## Наборы

| Dataset | Язык | Что классифицируется | Ограничения источника |
|---|---|---|---|
| [BANKING77](https://huggingface.co/datasets/PolyAI/banking77) | Английский | 77 классов обращений по онлайн-банкингу | Карточка описывает banking support queries, но не полностью раскрывает исходный процесс сбора текстов; нельзя уверенно утверждать, что это сырой экспорт обращений реальных банковских клиентов. |
| [CLINC150](https://huggingface.co/datasets/DeepPavlov/clinc150) | Английский | Разнообразные интенты; опубликованный вариант включает out-of-scope примеры | Краудсорсинговый исследовательский бенчмарк, а не подтверждённый производственный архив клиентской поддержки. Источник и лицензия upstream описаны в [UCI](https://archive.ics.uci.edu/dataset/570/clinc150). |
| [MASSIVE](https://huggingface.co/datasets/AmazonScience/massive) | В том числе русский | 60 интентов голосового помощника | Уже проверялся отдельным экспериментом; локализованные запросы к голосовому помощнику не являются запросами о металлопрокате. |

Синтетические датасеты, например Bitext customer-support training data, не включаются в этот набор и не называются реальными клиентскими сообщениями.

## Протокол

1. Для каждого источника фиксируется разрешённая ревизия Hugging Face Hub.
2. В модельный конвейер поступает только официальный train; официальный test применяется после выбора метода и только для отчётных метрик.
3. Перед AMORPH удаляются все точные нормализованные тексты с конфликтующими метками; одинаковые тексты с одинаковыми метками схлопываются. Тексты не переписываются и метки не угадываются.
4. Для выполнения near-duplicate audit на текущем лимите AMORPH размер выборки ограничивается на класс фиксированным seed. Поэтому это ограниченный воспроизводимый эксперимент, а не попытка объявить результатом официального leaderboard на полном обучающем наборе.
5. Сравниваются TF-IDF и multilingual-e5-small с заранее указанной конфигурацией логистической регрессии C=0.1, class_weight=balanced. Test не используется для выбора.
6. В артефакт сохраняются версии, хэши канонических наборов/выборки, отчёт AMORPH, отчётные метрики, результат Proof Gate и SHA-256-инвентарь. Исходные тексты и CSV не загружаются.
7. Ставки стоимости по умолчанию равны нулю. Полученные TCO-оценки нельзя трактовать как реально измеренную денежную стоимость.

## Что этот эксперимент не доказывает

- Датасеты не содержат стабильного customer_id / source_id, пригодного для независимого group split. Создавать фиктивные группы нельзя.
- Английские интенты банкинга и общего помощника — не домен продажи металлопроката.
- Успешный публичный тест не закрывает пункт 8 docs/READINESS.md — проверку CSV на домене владельца.
- INCONCLUSIVE в Proof Gate не является успехом; совпадение метрики с самим собой не считается доказанным улучшением.
- Текущий Selector использует runtime proxy и не доказан как денежный глобальный TCO-оптимизатор.

## Что найдено по домену владельца

Поиск не выявил публичного набора с одновременно подтверждёнными реальными русскоязычными B2B-обращениями по продаже металлопроката и проверенной ручной разметкой по интентам. Это пробел публичной доступности, а не доказательство, что такого набора нигде нет. Открытая русскоязычная статья по e-commerce intent classification также отмечает, что автору не удалось найти пригодный русскоязычный датасет поддержки ритейла: [Habr, 9 февраля 2024](https://habr.com/ru/articles/792542/).

Для проверки на собственном домене нужен небольшой обезличенный CSV из настоящей истории обращений с согласованной разметкой: текст, основной интент и при необходимости стабильный псевдоним клиента/диалога. Персональные/коммерческие сведения не следует отправлять в публичный репозиторий.
