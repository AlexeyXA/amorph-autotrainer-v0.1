# Инструкция владельцу: первый запуск на реальных данных AMORPH AutoTrainer v0.1

> Цель — выполнить один воспроизводимый запуск на своём CSV, сохранить доказательства запуска и корректно прочитать вердикт. Это не обещание, что модель пройдёт gate или будет готова к production.

## 1. Правила до запуска

1. Используйте данные, которые разрешено обрабатывать локально. Не загружайте частный CSV в GitHub, Issue, PR или публичный notebook.
2. До просмотра gate определите, что является одной независимой единицей: пользователь, клиент, проект, документ, диалог, источник и т. п. Если строки из одной единицы могут коррелировать, нужна подходящая колонка идентификатора группы.
3. Если задача — предсказать будущее, случайное разбиение по группам не заменяет хронологическое разбиение. Встроенная команда `amorph-autotrainer train` не является готовым временным backtest. При временной задаче сначала зафиксируйте отдельный time-split протокол.
4. Зафиксируйте критерии до запуска. Не меняйте margin/порог после просмотра gate ради получения `ACCEPT`.
5. Сначала прочитайте [ограничения Proof Gate](PROOFGATE_LIMITATIONS.md). `ACCEPT` означает прохождение заданных условий на конкретной gate-выборке, а не универсальную гарантию качества.

## 2. Формат CSV

По умолчанию нужны как минимум две колонки:

- `text` — входной текст, по которому надо предсказать класс;
- `label` — правильная метка класса.

Если зависимые строки должны оставаться в одной части, добавьте непустую колонку, например `customer_id`, `source_id` или `project_id`. Название должно отражать реальную зависимость, а не быть случайным номером каждой строки.

Проверьте перед запуском:

- первая строка содержит уникальные заголовки;
- в каждой используемой строке заполнены текст и метка;
- нет случайно повреждённых CSV-строк;
- ID группы заполнен у каждой строки, если вы его используете;
- метки имеют устойчивые определения, а не меняются от строки к строке;
- каждый целевой класс представлен достаточным количеством примеров. Встроенный минимальный порог gate по умолчанию — 5 строк на класс; это операционный предохранитель, не математическая гарантия мощности.

Не включайте в публичные репозитории настоящие имена, телефоны, email, адреса, коммерческие секреты или другие поля, которые не нужны для обучения. Хеширование CSV не обезличивает сам CSV.

## 3. Установка в Windows PowerShell

Откройте PowerShell. Если репозиторий ещё не скачан:

```powershell
git clone https://github.com/AlexeyXA/amorph-autotrainer-v0.1.git
Set-Location .\amorph-autotrainer-v0.1
```

Если каталог уже есть, перейдите в него через `Set-Location`. Для воспроизводимого запуска используйте проверенный commit `612633012d0eb26892473328213ce35c5befc52e` или более поздний commit после прохождения CI и просмотра изменений.

Создайте виртуальное окружение и установите обычные тестовые зависимости:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -e ".[test]"
pytest -q
```

Если PowerShell блокирует активацию окружения, можно разрешить скрипты только в текущем процессе PowerShell:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

Чтобы сравнить TF-IDF с E5, установите дополнительную зависимость:

```powershell
pip install -e ".[embeddings]"
```

E5 скачивает модельные веса из Hugging Face и требует сетевого доступа. GPU для первого запуска TF-IDF не нужен. Если веса недоступны, можно проверить обработку CSV через TF-IDF-only, но такой запуск без challenger ожидаемо даст `INCONCLUSIVE / SELF_COMPARISON` и **не докажет приёмку модели**.

## 4. Храните CSV и результаты вне Git-репозитория

Пример путей ниже — замените их на свои. Используйте папку вне клонированного репозитория, чтобы частные данные и отчёты случайно не попали в коммит.

```powershell
$Csv = "D:\AMORPH-private\my_data.csv"
$Out = "D:\AMORPH-private\runs"
New-Item -ItemType Directory -Force -Path (Split-Path $Csv), $Out | Out-Null
Get-FileHash $Csv -Algorithm SHA256
```

Перед запуском проверьте, что `$Csv` указывает на ваш CSV, а названия колонок совпадают с его заголовками. Не вставляйте реальные строки из файла в issue для демонстрации.

## 5. Основной запуск на вашем домене

### Вариант A — есть корректная колонка групп

Следующая команда — пример. Замените `text`, `label` и `customer_id` на реальные названия колонок. `customer_id` должен обозначать реального клиента/источник зависимости; не используйте его просто потому, что так написано в примере.

```powershell
amorph-autotrainer train $Csv --text-column "text" --label-column "label" --group-column "customer_id" --out $Out --strategies "tfidf,e5" --max-candidates 2 --seed 42 --noninferiority-margin 0.01 --bootstrap-samples 500 --min-gate-examples-per-class 5
```

### Вариант B — строки действительно независимы

Уберите только параметр `--group-column "customer_id"`. Не выбирайте этот вариант, если у вас есть повторные строки от одного пользователя/клиента/источника, коррелирующие документы или диалоги.

### Что означает эта команда

- `tfidf,e5` заранее фиксирует сравнение дешёвого TF-IDF-baseline и E5 с текущими production-defaults проекта; эта команда **не** меняет defaults.
- `--seed 42`, margin `0.01`, 500 bootstrap-повторов и минимум 5 примеров на класс фиксируют параметры этого запуска. Если в вашем рабочем процессе нужны другие пороги, определите их до просмотра gate и запишите причину.
- Без `--min-macro-f1` абсолютная предметная цель качества не задаётся. Не называйте модель достаточно хорошей для бизнеса только на основании `ACCEPT`; при наличии согласованного абсолютного порога добавьте, например, `--min-macro-f1 0.80` **только если 0.80 действительно является заранее утверждённым порогом для вашей задачи**.
- Нулевые ставки вычислений/работы человека по умолчанию означают, что эти затраты предполагаются бесплатными. Для денежной оценки TCO нужно заранее внести реальные ставки и ожидаемый объём запросов; это не меняет статистический вердикт автоматически.
- Не запускайте серию конфигураций в попытке «выбить ACCEPT» на одном и том же gate. Любая настройка после просмотра gate делает этот набор менее независимым для подтверждающих заявлений.

Запуск может занять время при первой загрузке E5. Общий лимит времени по умолчанию — 7200 секунд; активный вызов сторонней библиотеки не всегда можно прервать немедленно.

## 6. Где смотреть результат

В PowerShell определите каталог последнего запуска:

```powershell
$Run = Get-ChildItem $Out -Directory |
  Sort-Object LastWriteTime -Descending |
  Select-Object -First 1
$Run.FullName
```

Проверьте ключевые файлы, созданные в этом каталоге:

- `report.json` — итоговый manifest отчёта запуска, конфигурация, метрики и предупреждения;
- `manifest.json` — manifest и provenance;
- `replay.json` — описание воспроизведения и ссылки на split/hash;
- `data_report.json` — отчёт о данных и разбиении;
- `proofgate\selected_candidate.json` — вердикт выбранного кандидата;
- `proofgate\baseline_reference.json` — отчёт базового self-comparison;
- `selected\manifest.json` — manifest выбранной итоговой модели.

Выведите основные поля из manifest:

```powershell
$M = Get-Content (Join-Path $Run.FullName "manifest.json") -Raw | ConvertFrom-Json
$M.status
$M.strategy
$M.proofgate.selected_candidate_verdict
$M.proofgate.selected_candidate_subtype
$M.proofgate.decision_passed
$M.proofgate.legacy_parity_status
$M.dataset_sha256
$M.proofgate.selected_candidate_report_sha256
$M.test_split_used_for_selection
$M.warnings
```

Создайте локальную ведомость SHA-256 для файлов запуска:

```powershell
Get-ChildItem $Run.FullName -File -Recurse |
  Get-FileHash -Algorithm SHA256 |
  Select-Object Path, Hash |
  Export-Csv (Join-Path $Out "artifact-hashes.csv") -NoTypeInformation -Encoding UTF8
Get-FileHash (Join-Path $Run.FullName "report.json") -Algorithm SHA256
Get-FileHash (Join-Path $Run.FullName "manifest.json") -Algorithm SHA256
Get-FileHash (Join-Path $Run.FullName "replay.json") -Algorithm SHA256
```

Храните результаты локально. Внутренний `report_sha256` Proof Gate и SHA-256 самого JSON-файла — разные хешируемые объекты; запишите их под разными подписями.

## 7. Как интерпретировать вердикт

- **`ACCEPT`** — кандидат прошёл заранее заданные условия Proof Gate на этой gate-выборке. Проверьте, что это реальный challenger, `legacy_parity_status=match`, данные/split корректны и абсолютная бизнес-цель (если задана) пройдена. Этот вердикт не доказывает устойчивость к временным изменениям, всем сегментам или будущим данным.
- **`REJECT`** — заданный критерий challenger не пройден. Не обходите отказ, меняя margin после факта; изучите отчёт и при необходимости соберите независимые новые данные.
- **`INCONCLUSIVE`** — данных или условий недостаточно для приёмки: например, нет реального challenger, предсказания совпали, gate underpowered или входы не прошли conformance. Это **не** успех и не доказательство того, что модель плохая.
- **`baseline_only` / `baseline_self_comparison`** — сохранён TF-IDF-baseline без статистической приёмки альтернативы.
- **Exit code 0 не означает `ACCEPT`**: валидный `INCONCLUSIVE` тоже может завершиться кодом 0. Код 1 означает ошибку запуска; 2 связан с провалом заданной абсолютной цели; 3 — исчерпание runtime budget; 4 — недостаточный acceptance gate. Смотрите сам report и Proof Gate verdict, а не только код процесса.

Финальный test в этом pipeline является report-only и не участвует в выборе стратегии или решении rollback. Его метрики могут оказаться в отчёте, но не используйте их для подбора модели.

## 8. Что безопасно передать в Issue #1 для совместного разбора

Передайте только компактную обезличенную сводку:

- commit SHA проекта и UTC run ID;
- число строк, число классов и число групп (без текстовых примеров и личных значений);
- названия стратегии и заранее зафиксированные критерии;
- `status`, Proof Gate `verdict` и `subtype`, `decision_passed`, `legacy_parity_status`;
- dataset/source SHA-256, split hashes, report SHA-256, manifest/replay file hashes;
- факт наличия предупреждений (можно кратко пересказать без пути к личным файлам).

Не отправляйте сырой CSV, содержимое текстовых строк, список ID групп, выгрузки признаков, персональные данные, секреты или весь отчёт без предварительной проверки. Если отчёт содержит чувствительные имена классов/пути/метаданные, перед публикацией сделайте отдельную безопасную сводку, сохранив полный оригинал локально.

## 9. Когда пункт готовности считается выполненным

Owner-data пункт `docs/READINESS.md` можно считать подтверждённым только после фактического запуска на доменных данных владельца и проверки provenance. Сам факт запуска закрывает лишь доказательство интеграции с конкретным CSV; он **не** гарантирует `ACCEPT`. Если результат `INCONCLUSIVE` или `REJECT`, так и запишите — это честный результат эксперимента, а не причина скрывать отчёт.

Пока такой прогон не выполнен, не объявляйте продукт готовым для конкретного рабочего домена и не начинайте расширение модельного зоопарка, настройку на просмотренном official test или денежную TCO-оптимизацию под видом закрытия этого readiness-пункта.
