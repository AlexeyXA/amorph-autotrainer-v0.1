# MASSIVE ru-RU hybrid experiment — predeclared protocol

**Status:** experiment specification, written before the hybrid benchmark result is available.  
**Implementation:** PR #8 (hybrid_tfidf_e5, experimental; not enabled by default).  
**Scope:** the pinned MASSIVE ru-RU intent-classification dataset only.

## Fixed data and model versions

- Dataset: AmazonScience/massive, revision c4aa61e89895160619e18a94de72f19b99e72ca2.
- Dense encoder: intfloat/multilingual-e5-small, revision 614241f622f53c4eeff9890bdc4f31cfecc418b3.
- Internal grouping key: worker_id; random seed 42.
- Internal acceptance gate: at least five examples/class and 500 paired bootstrap resamples.

## Candidate set fixed before execution

| Candidate | LogisticRegression C | class_weight | Fusion |
|---|---:|---|---|
| tfidf | existing baseline config | existing baseline config | word + char TF-IDF |
| e5 | 0.1 | balanced | normalized multilingual E5 |
| hybrid_tfidf_e5 | 1.0 | None | word/char TF-IDF plus normalized E5; lexical block scaled by 1/sqrt(2) |

The E5 setting is the previously recorded validation/gate-qualified candidate. The hybrid setting is an initial, un-tuned configuration. Do not alter either setting in response to official-test scores. The experiment adds one hybrid only; it does not introduce BGE/GTE or a Cartesian product of embedders.

## Decision protocol

1. All requested candidates use the same prepared official-training rows and internal split generated by AMORPH.
2. The selector sees internal validation only. Its existing objective is a runtime proxy, not monetary TCO.
3. The independent acceptance gate compares the selected non-baseline candidate against TF-IDF. If a challenger is rejected, TF-IDF remains the final candidate.
4. The official MASSIVE test partition is evaluated only after internal selection and gate processing. Per-class and aggregate official-test metrics are report-only; they do not feed selection, acceptance, or rollback.

## Limitation that must not be hidden

The official MASSIVE test has already been inspected for earlier TF-IDF and E5 variants. Therefore this hybrid run is **not** an untouched final holdout experiment, even though the pipeline does not use test labels for selection/gating. Treat hybrid official-test scores as retrospective descriptive results only. Do not use those scores to tune the next configuration and then claim an unbiased final test. A stronger final generalization claim requires a newly reserved external dataset/holdout.

## Reproduction command

~~~bash
python scripts/benchmark_massive_ru.py \
  --with-e5 \
  --with-hybrid \
  --e5-classifier-c 0.1 \
  --e5-class-weight balanced \
  --hybrid-classifier-c 1.0 \
  --hybrid-class-weight none \
  --output-dir benchmark_runs/massive_ru_hybrid_e5 \
  --max-runtime-seconds 7200
~~~

The benchmark output and per-class report are provenance artifacts, not claims of superiority.
